# 풀리지 않은 질문

원고를 쓰다가 받은 문서로 답하지 못한 질문을 적는다. 답을 찾으면 지우지 않고 "답"을 채운다.

| 번호 | 장 | 질문 | 왜 답하지 못했는가 | 답 |
|---|---|---|---|---|
| 1 | 3, 부록 A | QM은 무엇을 뜻하는가 (일반적인 품질 관리로 충분하다는 뜻인가) | 미국 정부의 보고서는 약어만 풀고, 표의 결과와 요구사항의 예로만 쓴다 |  |
| 2 | 6, 7 | FTTI의 규격 정의와, 그것을 나눈 시간 구간의 이름과 관계 | 보고서에는 정의 문장이 없다. AUTOSAR의 문서는 '보통 알아채는 시간과 대응하는 시간의 합'이라고만 적는다. 그래서 예제는 FTTI라는 이름을 쓰지 않는다 |  |
| 3 | 7 | ASIL decomposition의 조건 (독립의 뜻, 나눈 뒤의 등급 표기) | 보고서는 '독립을 보일 수 있으면 다른 등급으로 구현할 수 있다'까지만 적는다. 그래서 규칙을 설명하지 않고 예제에서도 쓰지 않는다 |  |
| 4 | 7, 11 | E-Gas monitoring concept의 세 단계는 각각 무엇인가 | 받은 문서에는 이름과 구현 위치만 나온다. 예제의 구조는 이 책의 설계로 제시했다 |  |
| 5 | 19, 5 | 확인 검토를 하는 사람이 만든 사람에게서 얼마나 독립이어야 하는가 (등급별 규칙) | ISO 26262 Part 2의 표를 가리키는 문장만 있다 (2011 판) |  |
| 6 | 부록 A, 8 | latent fault의 규격 정의 | 보고서는 낱말만 쓴다. 용어집의 풀이는 이 책의 것이다 |  |
| 7 | 6, 예제 | inverter가 토크를 끄는 방법에 따라 원치 않는 제동 토크가 생기는가 | 보고서는 inverter가 토크 0을 만드는 방법을 다루지 않는다. 가정 A-07에 남겼다 |  |
| 8 | 부록 E | CAN frame의 구조와 CAN이 스스로 잡는 오류의 범위 | 받은 문서에 CAN을 설명한 것이 없다. 부록 E는 통신의 고장 종류만 AUTOSAR의 문서로 적었다 |  |
| 9 | 3 | ALARP, demand mode, systematic capability | 받은 문서에 설명이 없거나 한 줄뿐이다. 뼈대에서는 쓰지 않았다 |  |
| 10 | 4 | ISO 26262의 방법 표가 등급마다 권하는 정도를 다르게 적는가. 그 표기는 무엇인가 | 받은 문서에 없다. 4장에서 그 문장을 뺐다 |  |
| 11 | 5 | ISO 26262가 회사 사이의 책임 분담 합의를 무엇이라고 부르고 무엇을 넣게 하는가 (development interface agreement) | 받은 문서에 없다. 5장에서 그 문장을 뺐다 |  |
| 12 | 5, 19 | ISO 26262의 확인 활동 (confirmation measure)의 종류, 차량 수준의 validation과의 관계, 활동을 줄이는 규칙 | 받은 문서에는 용어의 이름과 2011년 판을 설명한 한 문장만 있다 |  |
| 13 | 4, 부록 B | ISO 26262와 IEC 61508의 어느 Part가 normative인가 | 발행 기관의 공개 페이지에서 확인하지 못했다 |  |
| 14 | 4 | ISO 26262 다음 판과 IEC 61508 Edition 3에서 무엇이 달라지는가 | 발행 기관이 공개한 변경 요약을 찾지 못했다 (2026-11-22) |  |
| 15 | 6, 예제 | safety goal은 hazard의 원인이나 대응 수단에 따라 나누어 적을 수 있는가. hazard의 일부만 담은 safety goal에 hazard의 등급을 그대로 주는가 | 받은 문서에 없다. 검토자의 기억으로는 나누지 않는다. 예제의 `SG-02`는 나누지 않고 세 구절로 적었다 |  |
| 16 | 8 | ISO 26262가 등급에 따라 연역적 분석과 귀납적 분석을 어떻게 요구하는가 | 받은 문서에 없다. 8장에 확인하지 못했다고 적었다 |  |
| 17 | 9 | ISO 26262의 하드웨어 지표가 single-point fault와 latent fault에 관한 것 둘뿐인가 | 보고서는 둘만 든다. 검토자의 기억으로는 하나 더 있다. 9장에 더 있을 수 있다고 적었다 |  |
| 18 | 7, 예제 | ISO 26262가 hardware-software interface의 명세에 무엇을 적으라고 요구하는가 | 받은 문서 여섯 개에 없다. 예제의 `hsi.md`는 분석에서 나온 것을 모았다 |  |
| 19 | 6, 7 | FTTI의 규격 정의. 끝점이 hazardous event인가 | 보고서에는 약어의 풀이와 쓰임만 있다 |  |
| 20 | 6, 예제 | 구동 토크를 한 번에 끊는 것이 차의 안정을 흔드는가. 내리는 기울기를 어떻게 정하는가 | 받은 문서에 없다. 예제는 가정 `A-26`으로 두었다. 차량의 시험이나 그 분야의 자료가 필요하다 |  |
| 21 | 12, 예제 | 뒤집은 사본 (`SWR-22`)과 고장 기록 (`SWR-23`)을 예제에 구현할 것인가 | 구현하지 않았다. 제품 코드가 955줄로 잡아 둔 상한 (850줄쯤)을 넘었고, 둘을 sim에서 보이려면 sim 쪽에 큰 장치가 필요하다. 12장은 둘을 설계로 설명한다. 구현하려면 제품 코드 100줄쯤과 sim의 실행기 (달리는 중에 다시 켜기, 비휘발성 memory)가 든다 |  |
