## 확인하지 못한 것

- ISO 26262와 IEC 61508의 본문에 관한 지적은 확인하지 못했다. 원문이 없기 때문이다. 검토자도 "기억에 의존, 미확인"으로 표시했다.
  - 예: FTTI를 나눈 시간 구간의 이름, ASIL decomposition의 세부 조건, V-model에서 safety validation의 위치, Annex의 제목.
- 그래서 이 지적들은 장 계획에 "다룰 항목"으로만 넣었다. 사실로 쓰기 전에 RULES.md 5절에 따라 확인한다.
- 두 검토자는 같은 계열의 모델이다. 두 검토가 일치한다고 해서 사실이 확인된 것은 아니다.

## 검토 뒤에 저자가 정한 것 (2026-11-22)

- 규격 원문을 구한다 (D-01).
- 독자는 임베디드 시스템 개발 경험이 있는 소프트웨어 엔지니어로 본다 (D-02). 검토의 권고와 다른 쪽이다.
  - 부록 E는 MCU의 기초를 빼고 차량 E/E만 다룬다. 장으로 올리지 않는다.
  - 장마다 두려던 "임베디드 상자"는 없앴다. 9장과 14장의 목표 쪽수를 줄였다.
  - 임베디드 엔지니어의 지적 가운데 독자에게 기초를 가르치자는 부분 (E-01의 MCU 입문)은 쓰지 않는다. 같은 주제를 안전의 관점에서 다루자는 부분 (startup과 reset, 공유 data, build 설정 등)은 그대로 둔다.
- 검토가 적은 장별 목표 쪽수의 합은 290쪽이 아니라 300쪽 안팎이었다. 문서의 합계를 고쳤다.
- 장 계획은 `plans/`에, 원고는 `chapters/`에 따로 둔다 (D-11). 검토 당시에는 한 파일에 있었다.
