# 2차: 통합안 (단계 2에서 예제를 넓히는 범위)

1차 의견 둘 (`round1-fusa.md`, `round1-embedded.md`)을 진행자가 합쳤다. 두 검토자는 상대의 1차 의견을 읽고 항목마다 답한다.

## 1차에서 일치한 것

- 방향 (열린 가지 넷과 한계 넷을 닫는다)에 동의. 열 가지를 같은 무게로 다 넣지는 않는다.
- D2: 감시가 변화율 상한을 갖는다. 기능에서 제한을 빼지 않는다.
- D3: 브레이크 접점 둘의 가정을 더한다. 접점 둘은 이 책의 선택이고, 보고서가 요구하는 것은 신호의 검사라는 것을 나눠 적는다.
- D4: 외부 watchdog의 model은 sim에만 둔다. "늦음"은 sim에서 흉내 낼 수 없다. 순서와 횟수가 맞으면서 값이 틀린 감시는 잡지 못한다고 적는다.
- D6: 55 Nm / 100 ms로 정하지 않고 오차와 시간의 예산에서 거꾸로 정한다. 견줄 기준은 깎은 뒤에 보낸 값이다.
- D7: 작은 형식으로 하고, 실제 profile과 다르다고 밝힌다.
- 순서: 문서를 먼저 쓰되, 요구사항의 숫자를 굳히기 전에 돌려서 잰다.
- M9는 진단과 경고의 몫이고 `SG-01`의 시간 안에 L1을 닫지 못한다. L1을 닫는 것은 D2다.

## 임베디드의 지적 가운데 그대로 받은 것

- debounce는 비대칭으로 한다: "밟음"은 빨리, "놓음"은 두 접점이 맞고 3주기 이어진 뒤에. 두 접점이 어긋난 채 이어지면 "밟음"으로 두고 고장으로 판정한다.
- 접점 둘이 connector와 전원을 함께 쓰면 공통 원인이 남는다는 것을 가정 목록에 적는다.
- 비휘발성 memory: 먼저 구동 허용을 끊고 그다음에 쓴다. 지우는 방법이 없으면 한 번 걸린 차가 영영 못 움직인다.
- 뒤집은 사본은 ECC가 있는 MCU에서는 중복이고, 최적화가 비교를 지울 수 있다. 대상을 고르는 기준을 장에 적는다.

## FuSa의 지적 가운데 그대로 받은 것

- debounce를 검사라고 부르지 않는다. M9를 L1의 해결로 적지 않는다. 뒤집은 사본을 memory 보호의 대표로 보이지 않는다.
- M4는 inverter가 알리는 토크가 실제 토크와 따로 계산된다는 가정을 새로 만든다. 가정 목록에 적는다.
- reset 뒤에는 기록을 읽은 다음에야 3주기의 대기가 끝나게 한다 (순서를 요구사항으로).
- CRC는 깎은 뒤의 값에 붙인다.

## 확인 요청

1. I1 - I16마다: 동의 / 수정 / 반대, 그리고 이유. 1차에서 자기 안과 다르게 정해진 항목 (FuSa: I8, I9. 임베디드: I1, I3, I5, I6, I7, I14)은 꼭 답한다.
2. I1의 모양에서 틈이 정말 닫히는가. 임베디드는 시제품을 I1의 모양으로 바꿔 같은 입력 넷과 무작위 입력으로 다시 잰다 (정상 기능이 깎이는 주기, 틈이 55 Nm 이상인 주기). FuSa는 I1에서 새로 생기는 틈이 없는지 본다 (예: 출력 단계가 고정한 뒤, 줄여 가는 상태에서).
3. I6의 상한 40 Nm와 I10의 숫자가 예산으로서 맞는가.
4. 남은 반대가 있으면 "쟁점"으로 적는다.
