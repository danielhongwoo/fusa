## 1. D1 - D8

| 번호 | 판정 | 이유와 안 |
|---|---|---|
| D1 | 수정 | 열 가지를 같은 무게로 넣지 않는다. 코드까지 가는 것: M1, M2 (아래 수정), M3, M4, M5, M6의 되읽기, D2. 문서와 작은 코드: M7 (변수 셋만), M8, M9. M10은 아래의 "상한을 `SG-01`에서 끌어내는" 단순한 꼴이면 구현한다. 말로만 두면 D8의 걱정이 그대로 남는다. mechanism마다 "이것을 빼면 `SG-01`을 어기는" 대조 test (단계 1의 `NC-001`처럼)가 없으면 넣지 않는다. 대조 test를 만들 수 없는 mechanism은 sim에서 닫는 가지가 없다는 뜻이다 |
| D2 | 수정 (방향은 동의) | 감시가 변화율 상한을 갖는 것이 맞다. 기능에서 제한을 빼는 대안은 보고서가 토크 계산에 올리고 내리는 속도의 profile을 요구사항으로 드는 것 (PDF 80쪽, 24번)과 어긋나고, debounce와 M9는 조건을 줄일 뿐 닫지 못한다 (3절). 다만 모양을 바꾼다: 감시의 상한을 "자기의 지난 허용값 + R"이 아니라 "출력 단계가 지난 주기에 실제로 보낸 토크 + R_m"으로 둔다. 자기 상태에서 쌓아 올리면 R_m > R_f인 만큼 틈이 주기마다 쌓인다 (10주기면 10배). 지난 출력에 기대면 틈은 어느 주기에나 (R_m - R_f) + 허용 오차로 묶인다. 지난 출력은 이미 출력 단계 (감시 쪽)의 값이고 기능의 값이 아니다. R_m은 기능과 따로 둔 상수이고, 0 근처의 시작 규칙 (지금 기능은 prev <= 0이면 25 Nm부터)과 부호가 바뀌는 경우를 두 방향 조건 (정상 기능이 넘지 않는다 / 틈이 55 Nm보다 작다)으로 요구사항에 적는다 |
| D3 | 동의 (조건) | 81쪽 (37번)이 요구하는 것은 브레이크 신호의 "타당성과 정확성의 검사"이고 접점 둘은 이 책의 선택이다. 그렇게 나눠 적는다. 가정은 `A-02`와 같은 꼴 (센서가 주는 것)이어서 문제를 가정으로 푸는 것이 아니다. 대신 왜 반대 논리의 접점인가를 적는다: 공통 전원이나 접지가 끊기면 두 접점이 서로 어긋나 보이므로 공통 원인이 드러난다. 같은 논리의 접점 둘이면 함께 "놓음"이 된다 |
| D4 | 동의 (조건) | model은 sim/에 두고 제품 코드에 두지 않는다. `A-10`을 값이 있는 가정으로 고친다: 창의 길이, 답의 규칙, 끊을 때까지의 시간. 그 시간을 5절의 시간 예산표에 한 줄로 넣는다. 그리고 이 감시가 보지 못하는 것을 같은 쪽에 적는다: 순서와 횟수가 맞게 돌면서 틀린 값을 계산하는 감시는 지나간다 (그것은 M6, M7의 몫) |
| D5 | 수정 | 속도를 받는 것은 동의한다. 그러나 "속도가 없으면 지금 기어를 유지"는 위험하다. 정지 중에 속도가 높은 값에 고착되면 운전자가 R을 골라도 D가 유지되고, 가속 페달을 밟으면 운전자가 고르지 않은 방향으로 출발한다. 이것은 `SG-01`의 가지다. 안: 운전자가 고른 기어와 받아들인 기어가 다르면 토크 0 (N과 같게)으로 간다. 받아들이지 않은 기어로 구동하지 않는다. 그리고 M2는 "N이나 P인데 D로 읽는" 가지 (fta.md E5)를 닫지 못한다. 유효한 부호이면서 틀린 값은 부호 검사로 못 잡는다. 기어 신호를 둘로 받거나 (보수 부호), 변속 레버를 따로 동작하는 제어기로 두고 그쪽이 보호된 메시지로 보낸다는 가정을 더한다. 어느 쪽도 아니면 G7의 기어 쪽은 열린 채 적는다 |
| D6 | 수정 | 판정값은 오차의 예산에서 끌어낸다. `SG-01`의 55 Nm는 감시의 허용 오차 (5 Nm), inverter의 오차 (`A-05`, 값이 없다), M4의 판정값이 함께 쓰는 한 예산이다. inverter가 54 Nm 넘게 내고 감시가 5 Nm를 더 허용하면 합이 55를 넘는다. 견줄 기준은 기능의 요구가 아니라 출력 단계가 보낸 값이고, `A-14`의 2 ms와 `A-16`의 응답을 거친 예상값과 견준다. 시간은 판정 100 ms + 다음 주기 10 + 전달 1 + 토크가 내려가는 시간 60 = 171 ms로 200 ms 안이지만 여유가 작다. 거짓 차단: `A-16`에서 250 Nm에서 0으로 내릴 때 차이가 55를 넘는 시간은 약 30 ms여서 100 ms면 여유가 있다. 방향 (부호)도 본다 |
| D7 | 동의 (조건) | 받은 문서 (`references/autosar-e2e-protocol`)의 쪽을 근거로 든다. 이 책의 형식이 어느 profile과도 같지 않다고 밝힌다. 잔여 오류율이나 검출률의 숫자는 쓰지 않는다. CRC는 깎은 뒤의 값에 붙인다 (깎기와 포장 사이의 고장을 덮으려면) |
| D8 | 수정 | `H-04`에도 safety goal과 FSR 두셋까지는 내린다. 이미 `TSR-03`의 첫째 조건 (정상 기능은 허용 토크를 넘지 않는다)은 `H-04`의 요구사항이다. 이름을 붙여 주지 않았을 뿐이다. M1 불일치, M2 기어 불일치, M4, M5, M8, M10이 모두 토크를 끊는 쪽으로 가므로, 거짓 차단의 조건을 요구사항으로 두지 않으면 맞바꿈은 말로만 남는다. FMEA와 STPA는 `SG-01`만 끝까지 한다 |

## 2. mechanism마다: 닫는 가지와 새로 여는 가지

| 번호 | 닫는 가지가 맞는가 | 새 고장 방식, 새 가정 |
|---|---|---|
| M1 | E4 (밟았는데 놓음)를 닫는다. 맞다 | 두 접점이 어긋날 때의 판정 (`SG-01` 쪽은 "밟음"으로, 그러면 `H-04`). debounce가 제동 우선을 늦춘다: "밟음"으로 가는 쪽은 늦추지 않고 "놓음"으로 가는 쪽만 늦추는 비대칭이 맞다. 접점 하나의 고착은 페달을 밟을 때만 드러나는 숨은 고장이다 (발견까지 한 번의 제동) |
| M2 | D와 R 사이의 주행 중 바뀜만 닫는다. E5 전체가 아니다 (D5) | 속도 신호의 지연, 고착, 소실. 받아들인 기어를 누가 갖는가: 기능과 감시가 따로 가지면 틈이 생긴다 (4절). 운전자의 요구를 무엇으로 재는가 (고른 기어인가 받아들인 기어인가)를 정의한다 |
| M3 | G8은 VCU가 보호를 붙이는 데까지만 닫는다. 나머지는 inverter가 검사한다는 가정 | counter를 만드는 task가 멈추면 counter가 멈춘다: inverter의 timeout (`A-17`)과 M5가 겹치는 곳을 정리한다. 받는 메시지의 timeout마다 반응을 정한다 (속도 소실 -> M2, inverter 상태 소실 -> M4가 눈을 잃는다) |
| M4 | G6의 일부 (inverter가 요구보다 크게 낸다)만 닫는다 | inverter가 알리는 토크가 실제 토크와 따로 계산된다는 가정이 새로 필요하다. 전류 센서의 고장으로 크게 내는 inverter는 알리는 값도 틀린다. 반응 (구동 허용 차단)이 듣는다는 것은 여전히 `A-07`이다. 메시지가 멈춘 값이면 거짓 차단이나 놓침 |
| M5 | G5 가운데 "감시가 실행되지 않음, 순서가 틀림, 늦음"과 L4를 닫는다 | 감시의 답을 만드는 code 자체가 고장 나 늘 맞는 답을 내는 경우. 답을 감시 task 안의 계산 결과에서 만들어야 한다 (끝에서 상수를 내면 지나간다). sim의 실행 시간이 0이므로 "늦음"은 넣어 준 값으로만 보인다 |
| M6 | G5의 숨은 고장 가운데 구동 허용 차단의 경로를 닫는다 (되읽기). 깎기와 고정의 논리를 알려진 입력으로 돌리는 것은 sim에서 닫는 가지가 없다 | 되읽기 입력 자체의 고착 (늘 "끊김"이면 시험이 거짓으로 통과). 시험 중 구동 허용을 한 번 켜야 하므로 그동안 토크 요구 0을 보장하는 순서. 논리 시험이 잡는 것은 하드웨어 (ALU, RAM, flash)의 고장이고 소프트웨어 결함이 아니라는 것을 적는다 |
| M7 | 고른 변수의 bit 반전을 닫는다 | 사본은 틀린 값을 계산해 넣는 고장을 못 잡는다 (틀린 값의 보수가 함께 들어간다). 어떤 변수인가: 고장 상태, counter 외에 D2의 지난 출력, M2의 받아들인 기어, M10의 상태도 들어가야 한다. 실제 제품의 memory 보호는 ECC와 MPU라는 것 (`A-19`)을 같은 쪽에 적는다 |
| M8 | L2를 닫는다. 그러나 L2는 `SG-01`을 바로 어기는 가지가 아니다: reset 뒤에도 감시가 다시 깎고 50 ms 안에 고정한다. 닫는 것은 고장이 숨은 채 노출되는 시간이다 | 쓰는 도중의 reset (고장을 놓침), 망가진 기록 (안전한 쪽으로 읽으면 `H-04`). watchdog reset은 software가 기록할 틈이 없으므로 reset 원인을 고장으로 다뤄야 한다. 지우는 조건 (정비)을 정한다 |
| M9 | L1의 원인을 진단하지만 `SG-01`의 시간 안에 닫지 못한다. 80 ms마다 한 번 끊기는 경우 200 ms 안의 실패는 2-3번이다. M을 그만큼 낮추면 잡음에 거짓 판정 | 판정 창과 FTTI의 관계를 요구사항에 적는다. M9의 몫은 경고와 숨은 고장의 발견이고 `SG-01`의 몫은 D2라고 나눠 적는다 |
| M10 | L3를 닫는다. 그러나 `SG-01`의 G2가 기대는 가정 `A-02` (두 채널이 함께 틀리지 않는다)의 바탕이 사라진다. 남은 채널이 범위 안에서 틀리면 (offset, 고착) 아무도 모른다. 감시도 같은 채널을 쓰므로 단일 고장이다 | 안: 줄여서 가는 상태의 토크 상한을 `SG-01`의 55 Nm에서 오차를 뺀 값 아래로 둔다. 그러면 남은 채널이 어떻게 틀려도 `SG-01`은 지켜진다. 이것보다 큰 상한을 원하면 그 근거는 controllability가 되고 가지가 열린다. 고장 채널은 범위 검사로만 가릴 수 있다: 두 채널이 범위 안에서 어긋나면 어느 쪽이 맞는지 모르므로 토크 0이다. 보고서도 채널 하나의 고장에 "천천히 올리는" 상태와 amber 경고를 든다 (PDF 68쪽, Safe State 3) |

## 3. 빠진 것, 넣지 말 것

꼭 필요한데 없는 것
- 오차의 예산표: 55 Nm를 감시의 허용 오차, R_m - R_f, inverter의 오차, M4의 판정값, 줄여 가는 상태의 상한이 어떻게 나눠 쓰는지 한 표로. 지금은 mechanism마다 따로 정해서 합이 넘을 수 있다 (D6).
- 시간 예산표의 확장: M1의 debounce, M2의 속도 timeout, M4, M5의 창, M9의 창이 각각 한 줄. 200 ms에서 시작해 거꾸로 나눈다.
- 고장 반응의 주인: 반응이 여럿 (토크 0, 구동 허용 차단, 줄여 가기, 경고)이 되므로 하나의 상태 기계가 감시 쪽에 있어야 한다. 없으면 M10이 줄여 가는 동안 M4가 끊고, 다음 주기에 M10이 다시 허용하는 식의 다툼이 생긴다. 상태 사이의 이동은 안전한 쪽으로만 간다는 규칙 (다시 켤 때까지).
- 공통 지점의 성장을 적는 것: M1의 판정, M2의 기어 결정, M10의 상태가 모두 기능과 감시가 함께 쓰는 입력 단계에 들어간다. 틈을 없애려면 같은 값을 봐야 하고, 독립하려면 따로 봐야 한다. 이 맞바꿈을 dependent failure analysis의 첫 항목으로 적는다. fta.md의 E3 (AND 아래에 있지 않은 가지)가 커진다.
- 기어 값의 보호 또는 정직한 열린 가지 (D5).

넣으면 잘못 가르칠 것
- M6의 "논리를 알려진 입력으로 돌려 보기"를 sim의 근거로 세는 것. sim의 software는 무작위로 고장 나지 않으므로 이 시험은 언제나 통과하고, 독자는 "켤 때 감시를 돌려 봤으니 감시가 옳다"를 배운다. 넣는다면 대상이 하드웨어라는 것과 sim에서 보이는 것이 없다는 것을 같은 쪽에 적는다.
- debounce를 검사라고 부르는 것. debounce는 튐을 거르는 것이고 고착을 찾지 못한다.
- 뒤집은 사본을 memory 보호의 대표로 보이는 것 (M7).
- M9를 L1의 해결로 적는 것.

## 4. 같은 종류의 틈이 새로 생기는 곳

단계 1의 교훈: 감시의 상한은 정상 동작의 모양 (envelope)을 따라야 하고, 정상 동작이 상태를 가지면 감시도 같은 상태를 알아야 한다. 아래는 그 규칙이 깨질 곳이다. 모두 "두 방향 조건"을 요구사항으로 적고 `TC-011`처럼 입력이 바뀌는 순서로 확인한다.

1. D2: 감시가 자기 값으로 쌓아 올리면 틈이 주기마다 쌓인다. R_m = R_f로 맞추면 정상 기능의 반올림 차이로 깎기가 이어져 고정된다 (`H-04`). 지난 출력 + R_m이 답이다 (1절).
2. M10: 줄여 가는 동안 기능의 상한과 감시의 허용 토크가 같은 상한과 같은 올리는 속도를 따라야 한다. 감시가 페달 값대로 250 Nm까지 허용하면 틈이 195 Nm다. 상태는 입력 단계 한 곳에서 정하고 둘에 같이 준다. 기능이 따로 정하면 단계 1의 F2-01 (기능만 아는 상태)과 같다.
3. M2: 받아들인 기어를 기능만 가지면, 감시는 운전자가 고른 R로 허용하고 기능은 D로 요구한다. 출력 단계가 방향으로 깎아 0이 되고 5주기 뒤 고정 (`H-04`). 반대로 감시만 가지면 기능의 요구가 계속 깎인다. 한 곳에서 정한다. 그리고 "운전자의 요구"의 기준을 받아들인 기어로 할지 정해야 틈을 잴 수 있다.
4. M1: 기능이 debounce한 값을, 감시가 날값을 쓰면 브레이크를 놓은 직후 감시가 먼저 허용하고 (틈), 밟은 직후 감시가 먼저 0으로 (거짓 깎기) 간다. 같은 값을 쓴다.
5. M4: 견줄 기준이 깎기 전의 요구이면 깎는 동안 기준이 부풀어 놓친다. 보낸 값 (깎은 뒤)과 견준다.
6. M3: 받은 속도의 timeout 동안 M2가 쓰는 값이 무엇인가 (마지막 값, 0, 무효). 마지막 값을 쓰면 멈춘 속도가 새 상태가 된다. 무효로 두고 D5의 규칙 (토크 0)으로.
7. M8, M5: reset 뒤 `TSR-07`의 3주기와 기록의 읽기 사이. 기록을 읽기 전에 3주기가 끝나면 한 번 토크가 나간다. 순서를 요구사항으로.

## 5. 3절의 순서

동의. 다만 단계 1의 무거운 결함 셋 (F-01, F2-01, F3-01)은 모두 sim에서 돌려 보고서야 드러났다. 묶음 2에서 요구사항을 굳히기 전에 4절의 틈을 scratchpad의 시험 code로 재서 틈의 표를 숫자로 채운다 (제품 code는 쓰지 않는다). 그래야 묶음 3에서 요구사항을 되돌리지 않는다. 묶음 2의 FMEA, STPA, DFA는 `SG-01`과 M10에 필요한 `H-04`까지로 좁힌다. hazard 다섯 전체로 넓히면 묶음이 문서의 양에 묻힌다.

## 6. 가장 큰 위험 하나

M10. "채널 하나가 고장 나도 남은 채널로 계속 간다"는 가용성의 이야기로 읽히지만, 실제로는 두 채널의 비교라는 G2의 바탕을 버리는 결정이다. 줄여 가는 동안 페달 경로는 단일 고장으로 `SG-01`을 어길 수 있는 지점이 되고, 감시도 같은 채널을 보므로 막지 못한다. 상한을 `SG-01`에서 끌어내지 않으면 독자는 "남은 채널이 범위 안이면 믿어도 된다"를 배운다. 버금가는 위험은 D5의 "기어를 유지"로, 고장 반응이 그 자체로 `SG-01`의 가지가 되는 경우다.

`(기억)` 규격의 safety mechanism은 고장의 검출과 반응을 FTTI 안에 끝내야 하고, 숨은 고장은 따로 다룬다는 틀이 있다. 이 검토의 논거는 그 기억에 기대지 않고 위의 가지로 적었다.
